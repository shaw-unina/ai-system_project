# Phase 3 — Data Strategy: Plan

## Context

Phase 1 picked the angle (LLM-paraphrase robustness + calibrated abstention on a RAG fact-checker). Phase 2 locked the contract (text-only English, ≤4 000 char input, structured `Verdict` output, AVeriTeC v2 as primary, 60 s/claim p95 latency).

Phase 3 turns that into a concrete **data plan**: which datasets we actually use, how we split them, how we generate the LLM-paraphrase attack set, how the ingestion pipeline is structured as reproducible code, and how datasets are documented (cards) and versioned. **No models train in Phase 3** — this is plumbing, splits, attack-set generation, and documentation. Phases 5–7 consume the artefacts produced here.

A late-breaking finding from the scouting search matters: the **FakeNewsNet** repo on GitHub does not redistribute article/tweet content. It ships CSV listings + a Twitter rehydration script. Since the Twitter API has been effectively closed to free-tier rehydration since 2023, FakeNewsNet's social-context features are no longer recoverable for new users. We will use **only the text portion** (article titles + the PolitiFact label CSVs) as a secondary slice, not as a primary benchmark.

## Goals

1. Lock the dataset list with explicit licences and provenance.
2. Define **time-ordered** splits that prevent temporal leakage and create a deliberate drift slice.
3. Specify the LLM-paraphrase attack-set generation pipeline (the "Virtual Hacker" companion) end-to-end, with quality controls.
4. Build the ingestion + preprocessing pipeline as **idempotent, hashed, versioned code** under `src/misinfo/data/`.
5. Produce dataset cards (Datasheets-for-Datasets style) for every corpus we use.
6. Pick one versioning approach (DVC vs raw + manifest hashes) and stick with it.

## Approach

### 1. Final dataset list (with licences)

| Use | Dataset | Source | Licence | Why |
|---|---|---|---|---|
| **Primary in-distribution eval** | **AVeriTeC v2** (FEVER 2025 task) | `huggingface.co/chenxwh/AVeriTeC` and `pminervini/averitec`; canonical FEVER 2025 task page | CC-BY-SA-4.0 (per the AVeriTeC repo and Schlichtkrull et al. 2024) | Real-world claims with web evidence; current SOTA benchmark. |
| **Secondary slice (text-only)** | **FakeNewsNet — PolitiFact text portion** | KaiDMML/FakeNewsNet GitHub | MIT for code; data subject to publisher / Twitter terms | Cheap drift / cross-domain slice; we use only `politifact_fake.csv` + `politifact_real.csv` (titles + URLs), no rehydrated tweets. |
| **Optional multilingual stretch** | **MuMiN-small** | `mumin-dataset.github.io` | Bespoke (non-commercial research) | Phase 7 stretch; English-only by default. |
| **Generated by us** | **LLM-paraphrase attack set** | Generated in Phase 3 from the AVeriTeC v2 fake-claim subset | Same CC-BY-SA-4.0 derivative for the *prompts*; sample set ≤ 50 claims released per Phase 2 ETHICS | The H1.a/b/c/d evaluation slices. |

Datasets explicitly **rejected** from the active list (with one-line reasons):

- **FEVER / FEVEROUS** — synthetic claims; saturated; we may use FEVER dev only as a sanity check.
- **LIAR / LIAR-PLUS** — short political statements with sparse evidence; not aligned with our claim+evidence contract.
- **ISOT** — known to be effectively solved on i.i.d. splits and to leak article-source information; deceptively strong baselines.
- **CheckThat! 2025 numerical claims** — interesting but a distinct task; out of scope per Phase 1.

### 2. Splits and slicing

For AVeriTeC v2 (the only primary):

- **Train** — Phase 5 baseline tuning only; we do not retrain the verifier (it is an open-weight LLM frozen at inference). Train split is therefore used for retriever calibration and prompt-development only.
- **Dev** — used for Phase 5 model selection, Phase 6 method development, and Phase 7 reporting of headline numbers (clean condition).
- **Test** — held out for Phase 7 final reporting only. **No tuning, no prompt iteration, no peeking.** Hash committed at Phase 3 close.
- **Time-ordered split for drift** — within dev, we induce a drift slice by sorting claims by `claim_date` and reserving the latest 20% as `dev_drift`. AVeriTeC v2's "new portion with more recent claims" already provides one — we adopt that as the drift slice when present.
- **Topic slices** for fairness (NFR-Fair-1/2) — derive from AVeriTeC's `claim_types` / `tags` field (politics, health, climate, …); hash the slice membership so it is reproducible.

For the LLM-paraphrase attack set:

- One paraphrase per fake claim per style (newswire / tabloid / social) → `n_attack = 3 × n_fake_claims_in_dev`.
- The same claim subset is reused across all H1 sub-hypotheses to enable paired bootstrap tests.

### 3. LLM-paraphrase attack-set generation

This is essentially Phase 6's "Virtual Hacker" companion, scaffolded in Phase 3 because it is data infrastructure.

Pipeline (`src/misinfo/data/attacks/paraphrase.py`):

1. Load the fake-claim subset of AVeriTeC v2 dev.
2. For each claim, prompt an open-weight paraphraser (default Llama-3.1-8B-Instruct or Qwen-2.5-7B-Instruct, 4-bit) with three style-specific system prompts.
3. **Quality gate** — every paraphrase passes through:
   - An NLI entailment check (DeBERTa-v3-MNLI): paraphrase must entail original at p ≥ 0.7 (label-preservation).
   - A near-duplicate check (BLEU < 0.85): paraphrase must not be a near-copy.
   - A length sanity check (within 0.5×–2× of the original).
4. Failed paraphrases get retried with temperature bump up to 3 times, then logged as `dropped`.
5. Final attack set is written to `data/processed/attacks/<style>/<dataset_hash>/*.jsonl` and a manifest CSV.

Determinism: all generation uses seeded `torch.manual_seed` and `transformers.set_seed`; the manifest records the exact model commit, prompt hash, and seed.

The attack set is **provisional** at Phase 3 close — it is generated again in Phase 6 against the chosen verifier model. Phase 3 produces a "spec attack set" used to validate the pipeline; Phase 6 may regenerate at scale.

### 4. Ingestion pipeline as code

New module: `src/misinfo/data/`

```
src/misinfo/data/
├── __init__.py
├── registry.py           # DatasetSpec dataclasses; central registry by name+version
├── loaders/
│   ├── averitec.py       # download (or read local), parse JSONL, validate schema
│   └── fakenewsnet.py    # parse the politifact_*.csv files; titles + URLs only
├── splits.py             # time-ordered split utility; topic-slice index builder
├── preprocessing.py      # length normalisation, character clipping (≤4000), unicode NFC
├── attacks/
│   ├── paraphrase.py     # the attack-set pipeline above
│   └── prompts/          # versioned prompts per style
└── manifest.py           # writes a deterministic manifest with sha256 hashes
```

Idempotency: every loader is `cache_or_compute(name, version) -> Path`. Re-running with the same `(name, version, raw_hash)` tuple returns the cached processed path without recomputation. The cache key is `sha256(raw_hash + preprocessing_version)`.

CLI entrypoints (Phase 5 wires these to `python -m misinfo.cli`):

```
misinfo data download averitec --version v2
misinfo data prepare averitec --version v2 --split dev
misinfo data attack-set --src averitec/v2/dev --styles newswire,tabloid,social
misinfo data verify          # checks every artefact's hash against manifest
```

### 5. Versioning approach

Decision: **manifest-only + DVC opt-in**.

- Every produced artefact gets a sha256 hash recorded in `data/manifest.json`. The manifest is committed.
- Raw downloaded data lives under `data/raw/<dataset>/<version>/` and is `.gitignore`d (already is per Phase 0).
- Processed artefacts live under `data/processed/...` and are also gitignored; they are reproducible from raw + code.
- DVC is **not** initialised in Phase 3. We add it later (Phase 9 or earlier) only if/when the team needs to share large artefacts across machines. The manifest gives us reproducibility without the infra burden.

Rationale: at this scale (a few GB), the manifest + reproducible pipeline is enough. DVC adds operational cost we don't yet need.

### 6. Dataset cards

For every dataset in §1, produce a card under `docs/data-cards/<name>.md` following the Datasheets-for-Datasets template (Gebru et al. 2021), pruned to the sections that bind:

- Motivation, composition, collection process, preprocessing/cleaning, uses, distribution, maintenance.
- **Known biases** — for AVeriTeC: English-only, fact-checker-organisation provenance bias, US-political skew. For FakeNewsNet (text portion): topical skew toward US politics + celebrity gossip; label noise from PolitiFact's six-class collapse.
- **Limitations** — what *not* to use the dataset for.

The attack set gets its own card explaining the dual-use posture (Phase 2 ETHICS).

### 7. Tests

Under `tests/test_data/`:

- `test_registry.py` — DatasetSpecs round-trip; version strings parse.
- `test_splits.py` — time-ordered split is deterministic and disjoint; topic slices cover the dev set.
- `test_preprocessing.py` — character clipping, NFC normalisation, idempotency.
- `test_manifest.py` — hashing is stable; verify CLI detects tampering.
- `test_attack_pipeline.py` — quality gates reject deliberately bad paraphrases (NLI fail, BLEU > 0.85, length out of band). Uses tiny fixtures, no real LLM.

The actual large-data downloads are **skipped in CI** behind a `--run-network` marker; they run locally on demand.

### 8. Risks

1. **AVeriTeC v2 access.** Some splits may require the FEVER 2025 task registration. Mitigation: confirm public availability of dev split; for test we may need to submit to the leaderboard rather than score locally.
2. **Paraphrase quality.** If the paraphraser hallucinates label-flipping content, the F1 drop is no longer a "style attack". Mitigation: NLI entailment gate + 10% manual spot-check per style. Failures are dropped, not scored.
3. **Disk / bandwidth.** The full AVeriTeC v2 evidence corpus is non-trivial. Mitigation: cache once locally, keep `data/raw/` gitignored, document the size in the dataset card.
4. **Twitter API closure.** Already handled by reducing FakeNewsNet to text only and demoting it to a slice.
5. **Topic slice imbalance.** Some AVeriTeC topical slices may have <30 examples — too few for fair F1. Mitigation: report only slices with n ≥ 30; document the omission.

## Verification

1. `pytest -q` — all new tests pass; large-data tests skipped.
2. `misinfo data prepare averitec --version v2 --split dev` succeeds locally; the resulting manifest hash is stable across two consecutive runs.
3. `misinfo data attack-set --src averitec/v2/dev --styles newswire,tabloid,social --limit 20` produces 60 paraphrases, each passing the NLI + BLEU + length gates.
4. `misinfo data verify` returns clean.
5. Each dataset card answers all Datasheets-for-Datasets sections we keep.
6. Traceability check: every NFR or hypothesis from Phase 2 that requires data has a dataset/slice entry mapped to it.

## Out of scope

- Training / fine-tuning any model (Phases 5–6).
- Retrieval-corpus construction beyond what AVeriTeC v2 ships with (Phase 4 ADR).
- DVC / remote artefact storage (deferred).
- Multimodal corpora (deferred per Phase 1).
- Synthetic-claim generation beyond the paraphrase attack styles (out of scope for the H1 study).
