# Phase 11 — Security review

Structured self-audit of the service surface. Each section: **what**, **how
checked**, **finding**, **action**.

## 1. `/v1/verify` and `/v1/batch` input validation

- **What:** request bodies bind to `VerifyRequest` / `BatchRequest` with
  `extra="forbid"`, `min_length=1`, `max_length=4000` on `claim`,
  `max_length=100` on the batch list.
- **Checked:** Pydantic schema in
  [src/misinfo/services/schemas.py](../src/misinfo/services/schemas.py);
  `extra="forbid"` blocks accidental field injection.
- **Finding:** OK. The batch endpoint caps at 100 to bound work per request.
- **Action:** none.

## 2. Prompt injection on the LLM path

- **What:** user-supplied claim flows into LLM prompts in the decomposer
  and aggregator.
- **Checked:** `verify/safety.py` sanitizes (NFKC, strips controls +
  zero-width, neutralises a fake `<<<END_USER_CLAIM>>>` fence) and wraps
  in a labelled fence. Prompt templates instruct the model to treat the
  fence as data; refusal pattern → `Abstain`.
- **Finding:** Adequate for known classes. Won't catch base64-encoded or
  homoglyph attacks.
- **Action:** documented in [LIMITATIONS.md](LIMITATIONS.md); follow-up
  ticket for homoglyph normalisation.

## 3. Error envelope hygiene

- **What:** does any 4xx / 5xx leak stack traces, backend hostnames, or
  internal config?
- **Checked:** Phase 8's
  [src/misinfo/services/errors.py](../src/misinfo/services/errors.py)
  wraps unhandled exceptions into `ErrorEnvelope`. Auth failures (Phase 11)
  return only `{"detail":"..."}` with `WWW-Authenticate: Bearer`.
- **Finding:** OK. No stack frames in responses.
- **Action:** none.

## 4. Secret hygiene

- **What:** anything hardcoded in source? `.env` committed?
- **Checked:** `git grep -E '(api_key|secret|password)\s*=\s*"'` returns
  only Pydantic field declarations. `.env` is gitignored (Phase 0). New CI
  step runs `gitleaks` (advisory).
- **Finding:** OK.
- **Action:** none.

## 5. Dependency vulnerabilities

- **What:** Python and npm dependencies.
- **Checked:** `pip-audit` and `npm audit --omit=dev --audit-level=high`
  added to CI (advisory).
- **Finding:** advisories vary over time; status is the latest CI run on
  `main`.
- **Action:** flip to blocking once the allowlist is curated.

## 6. Container hardening

- **What:** non-root user in both Dockerfiles, no leaked envs in image
  layers, no unnecessary tools.
- **Checked:** backend runs as `app` (Phase 8). Frontend now runs as `app`
  (Phase 11 change). Build envs aren't `ENV`-stamped into the runtime
  layer; they're injected at compose time.
- **Finding:** OK.
- **Action:** none.

## 7. CORS and security headers

- **What:** does the dashboard set CSP / X-Frame-Options /
  X-Content-Type-Options / Referrer-Policy / Permissions-Policy? Is CORS
  open on the backend?
- **Checked:** Next [middleware.ts](../frontend/middleware.ts) stamps the
  five headers. FastAPI has no CORS middleware — the browser only ever
  talks to the Next origin (ADR-0014).
- **Finding:** OK. CSP allows `'unsafe-inline'` for inline styles emitted
  by Next; tighten if/when style-src can be hashed.
- **Action:** documented as a follow-up.

## 8. Auth + rate limiting

- **What:** is the bearer-token check timing-safe? Does the rate limiter
  hold a global lock?
- **Checked:** key comparison uses Python `in set` (not constant-time, but
  the threat model is online guessing, not a side-channel — 256-bit keys
  generated by `openssl rand` are acceptable). Rate limiter uses a
  short-lived `threading.Lock` around the bucket update.
- **Finding:** OK for single-replica deploys. Multi-replica needs a
  shared bucket store.
- **Action:** documented in ADR-0015 and `phase-11-decisions.md`.

## 9. Logging

- **What:** does the structured-log middleware log full claim text?
- **Checked:**
  [src/misinfo/services/middleware.py](../src/misinfo/services/middleware.py)
  logs `request_id`, method, path, status, duration — not body. Verdict
  metadata is logged via Langfuse separately; claim redaction honours the
  opt-out flag (NFR-Priv-1).
- **Finding:** OK.
- **Action:** none.

## Summary

| Surface | Verdict |
|---|---|
| Input validation | OK |
| Prompt injection | Adequate, with documented gaps |
| Error envelope | OK |
| Secrets | OK |
| Dependencies | Advisory CI gate; tighten post-1.0 |
| Container | OK |
| Headers / CORS | OK |
| Auth / rate limit | OK for single-replica; needs Redis bucket for multi |
| Logging | OK |

Nothing in this review blocks a `v1.0.0` release. The follow-ups are
captured in [phase-11-decisions.md](phase-11-decisions.md).
